# Colors

The design system uses a two-tier color token architecture: **primitive** tokens define the raw palette, and **semantic** tokens map those primitives to meaningful use cases that adapt automatically across light and dark themes.

## Primitive vs Semantic Tokens

### Primitives

Primitive tokens are the base color palette. They have no opinion about _where_ they should be used. They are named by color family and shade:

```css
--primitive-neutral-800
--primitive-accent-primary-400
--primitive-utility-info-600
```

You generally should not use primitives directly in your components. They exist so the semantic layer can reference them. For rare edge cases (prototyping, one-off visuals), see the [Styling Guide](?path=/docs/styling-guide--docs#primitives-for-prototyping-and-edge-cases).

### Semantics

Semantic tokens describe _intent_ rather than color. Each one holds a light and a dark value (as a CSS `light-dark()` pair) and resolves to the right one for the active theme, so your code supports theming without conditional logic:

```css
--bg-surface-default      /* page/card backgrounds */
--fg-primary-bold         /* primary text color */
--outline-interactive     /* interactive element borders */
```

See the [Styling Guide, Colors section](?path=/docs/styling-guide--docs#colors) for usage patterns and best practices.

## Categories

Semantic color tokens fall into three groups, each targeting a specific CSS property:

- **`bg-`** sets `background-color`: surface fills, interactive backgrounds, status backgrounds.
- **`fg-`** sets `color`: text, icons, and other foreground elements. It also colors nested `GsIcon`s.
- **`outline-`** sets `outline-color`: borders and outlines on components.

An `icon-` utility takes the same names as `fg-` and colors only the icons inside an element, leaving its text color alone. Every color utility accepts an opacity modifier, such as `bg-surface-raised/50`.

## Using TypeScript Color Tokens

For non-CSS contexts like deck.gl layers, canvas rendering, or WebGL, the design foundation exports color tokens as TypeScript values:

```ts
import { designTokens } from '@wingbrace/glideslope-foundation/tokens'

// Values are RGBA arrays: [red, green, blue, alpha], every channel 0–255
designTokens.dark.bg.surface.default // [21, 21, 23, 255]
designTokens.light.bg.surface.default // [239, 241, 242, 255]
```

In a Vue app, prefer `useTheme().tokens` from `@wingbrace/glideslope`. It holds the color tokens for the active mode (plus the domain colors), follows mode changes, and includes any overrides passed to `provideTheme()`. See [Getting Started](?path=/docs/getting-started--docs#theming).

```vue
<script setup lang="ts">
import { useTheme } from '@wingbrace/glideslope'

const { tokens } = useTheme()
// tokens.value.bg.surface.default, tokens.value.outline.accent.primary.bold, ...
</script>
```

### Deck.gl Example

Deck.gl layers accept RGBA arrays directly, so the token values can be used as-is:

```ts
import { designTokens } from '@wingbrace/glideslope-foundation/tokens'

const { dark } = designTokens

new ScatterplotLayer({
  // ...
  getFillColor: dark.bg.accent.primary.bold, // [0, 79, 126, 255]
  getLineColor: dark.outline.accent.primary.bold,
})
```

### Token Structure

The exported `designTokens` object is organized by theme, then by category:

```
designTokens
├── dark
│   ├── bg        (surface, interactive, accent, info, advisory, normal, serious, critical)
│   ├── fg        (primary, inverse, disabled, hover, pressed, accent, info, advisory,
│   │              normal, serious, critical, a11y)
│   ├── outline   (static, interactive, accent, info, advisory, normal, serious, critical, mono)
│   └── shadow    (elevation: raised, overlay)
├── light
│   ├── bg
│   ├── fg
│   ├── outline
│   └── shadow
├── primitive
│   ├── neutral   (50–950)
│   ├── alpha     (black, white; 100–500)
│   ├── accent    (primary, secondary, tertiary; 50–900)
│   ├── utility   (info, advisory, normal, serious, critical; 50–900)
│   └── on        (accent)
├── domain
│   ├── classification (missing, unclass, cui, confidential, secret, top-secret, ts-sci)
│   └── roe            (pending, friend, assumed-friend, neutral, unknown, suspect, hostile,
│                       no-statement)
└── typography, spacing, radius, shadow, animation
```

Where a token has states, the default state is under `base`: `designTokens.dark.bg.interactive.bold.base`, `.hover`, `.pressed`.

Primitives are available for direct access:

```ts
import { designTokens } from '@wingbrace/glideslope-foundation/tokens'

designTokens.primitive.neutral['50'] // [255, 255, 255, 255]  (white)
designTokens.primitive.neutral['800'] // [33, 34, 35, 255]     (near-black)
designTokens.primitive.accent.primary['400'] // [0, 156, 222, 255]    (brand blue)
designTokens.primitive.accent.secondary['400'] // [34, 180, 201, 255]   (teal)
designTokens.primitive.alpha.black['300'] // [0, 0, 0, 61]         (black at ~24% opacity)
```
